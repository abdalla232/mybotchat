# بوت Telegram مع OpenAI — Python وRailway

مشروع جاهز لرفع ملفاته إلى GitHub ونشره على Railway. يدعم المحادثات النصية الخاصة، وسياق آخر 4 أسئلة وأجوبتها، وأوامر `/start` و`/help` و`/reset` و`/id`. النموذج الافتراضي `gpt-4.1-mini` ويمكن تغييره بمتغير بيئي.

**جاهز للنشر لا يعني منشورًا:** تحتاج حساباتك ومفاتيحك لإكمال الخطوات أدناه. لا تضع المفاتيح في المحادثة أو في ملفات GitHub.

## 1. إنشاء البوت عبر BotFather

1. افتح [BotFather الرسمي](https://t.me/BotFather) في Telegram.
2. أرسل `/newbot`.
3. اختر اسمًا ظاهرًا، مثل «مساعدي الذكي».
4. اختر اسم مستخدم فريدًا ينتهي بـ `bot`، مثل `my_ai_assistant_984_bot` إذا كان متاحًا.
5. سيعطيك BotFather توكنًا. احفظه لوضعه في `TELEGRAM_BOT_TOKEN`.
6. افتح رابط البوت الذي أعطاك إياه BotFather واضغط Start. لن يرد حتى يعمل المشروع على Railway.

الكود يضيف قائمة الأوامر تلقائيًا عند التشغيل. إذا انكشف التوكن، ألغِه وأنشئ بديلًا من BotFather ثم حدّث Railway.

## 2. تجهيز OpenAI API

1. افتح [منصة OpenAI](https://platform.openai.com/) وسجّل الدخول.
2. أنشئ مفتاحًا من [API keys](https://platform.openai.com/api-keys) ضمن مشروعك، مع صلاحية استخدام Responses API.
3. تأكد أن فوترة API مفعّلة وأن حسابك يستطيع استخدام النموذج المحدد.
4. ضع المفتاح في متغير `OPENAI_API_KEY` في الخطوة التالية.

تابع الاستهلاك من [Usage](https://platform.openai.com/usage). رصيد OpenAI API وتكلفة استضافة Railway حسابان منفصلان؛ لا تعتمد على تقديرات الأسعار الواردة في المحادثة السابقة. راجع [أسعار OpenAI](https://developers.openai.com/api/docs/pricing) و[أسعار Railway](https://docs.railway.com/pricing). عدد الرسائل الذي يغطيه مبلغ معين يعتمد على النموذج وطول الرسائل والسياق والردود.

## 3. رفع الملفات إلى GitHub

1. فك ضغط الحزمة.
2. أنشئ مستودعًا جديدًا في [GitHub](https://github.com/new)، ويمكن جعله خاصًا.
3. اختر **Add file → Upload files** وارفع محتويات مجلد المشروع، ثم احفظ عبر **Commit changes**.
4. تأكد أن `bot.py` و`Dockerfile` و`requirements.txt` و`railway.json` في جذر المستودع مباشرة، وليس داخل مجلد إضافي. يمكنك رفع مجلد `tests` والدليل أيضًا.
5. ارفع `.gitignore` و`.dockerignore` و`.env.example` إذا كانت الملفات المخفية ظاهرة لديك. لا ترفع ملف `.env` الذي يحتوي مفاتيح حقيقية.

## 4. النشر على Railway

1. افتح [Railway](https://railway.com/) وسجّل الدخول.
2. اختر **New Project → Deploy from GitHub repo**، واربط حساب GitHub إذا طُلب ذلك، ثم اختر المستودع.
3. Railway يبني المشروع باستخدام `Dockerfile` المرفق. إذا بدأ تشغيل أولي قبل إضافة المتغيرات فقد يفشل؛ أضف المتغيرات ثم انشر مجددًا.
4. افتح خدمة البوت ثم تبويب **Variables** وأضف القيم التالية. ضع القيم نفسها فقط، دون علامات اقتباس.

| المتغير | القيمة | الغرض |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | التوكن من BotFather | مطلوب |
| `OPENAI_API_KEY` | مفتاح مشروع OpenAI | مطلوب |
| `OPENAI_MODEL` | `gpt-4.1-mini` | النموذج الافتراضي |
| `OPENAI_IMAGE_MODEL` | `gpt-image-2.5-sunburst` | نموذج إنشاء الصور الأقوى للجودة |
| `OPENAI_IMAGE_QUALITY` | `high` | جودة الصور: `auto` أو `low` أو `medium` أو `high` أو `xhigh` أو `max` |
| `ALLOWED_USER_IDS` | اتركه فارغًا مؤقتًا | بعد التشغيل أضف رقمك من `/id` |
| `ALLOW_ALL_USERS` | `false` | حصر المحادثة بالمستخدمين المحددين |
| `MAX_OUTPUT_TOKENS` | `600` | الحد الأقصى لتوكنات الرد |
| `HISTORY_TURNS` | `4` | عدد أزواج السؤال والجواب المحفوظة؛ `0` يلغي الذاكرة |
| `MAX_INPUT_CHARS` | `3000` | أقصى طول للرسالة بالأحرف |
| `COOLDOWN_SECONDS` | `3` | أقل فاصل بين طلبين من المستخدم نفسه |

يمكن إضافة `SYSTEM_PROMPT` اختياريًا لتغيير أسلوب الرد، مثل: «أنت مساعد دراسي. اشرح ببساطة وبالعربية مع مثال قصير».

5. في **Settings** تأكد أن الخدمة تعمل في منطقة واحدة وبنسخة واحدة فقط (**Replicas = 1**). عطّل **Serverless / App Sleeping** إن كان مفعّلًا. لا تضف Cron Schedule.
6. اترك **Healthcheck Path** فارغًا. هذا المشروع عامل يعمل باستمرار ويجلب رسائل Telegram عبر polling، وليس موقع ويب؛ لا يحتاج Domain أو PORT أو Generate Domain.
7. أمر التشغيل هو `python bot.py` وموجود في الملفات. طبّق التغييرات واضغط **Deploy** حسب الواجهة.
8. في **Deploy Logs** ابحث عن `Bot initialized; starting polling`. هذه علامة بدء التشغيل، ويظل اختبار إرسال رسالة هو التأكد النهائي من الاتصال.
9. افتح البوت في Telegram وأرسل `/id`. هذا الأمر يعمل حتى قبل تفعيل حسابك للمحادثة.
10. انسخ الرقم إلى `ALLOWED_USER_IDS` في Railway، مثل `123456789`، وطبّق التغيير وانشر مجددًا.

لإضافة أشخاص آخرين: `123456789,987654321`. لجعل البوت متاحًا لكل من يراسله، غيّر `ALLOW_ALL_USERS=true`؛ عندها يتجاوز قائمة الأرقام المسموحة وتتحمل طلبات الجميع.

**لا تشغّل نسختين بالتوكن نفسه:** أوقف التشغيل المحلي قبل Railway. تجنّب نسخ المعاينة بنفس التوكن. الملف يضبط تداخل النشر إلى صفر، لكن قد يظهر تعارض عابر أثناء تبديل النسخ؛ التعارض المستمر يعني وجود مستهلك آخر للتوكن.

## 5. الاختبار بعد النشر

1. أرسل `/start` — يجب أن تظهر رسالة الترحيب.
2. أرسل «مرحبًا، جاوب بجملة قصيرة» — يجب أن يأتي جواب AI.
3. أرسل «اسمي سامر»، وانتظر بضع ثوانٍ ثم «شو اسمي؟» — يجب أن يستخدم السياق الحديث.
4. أرسل `/reset`، ثم «شو اسمي؟» — لا يعود اسمك السابق ضمن السياق المرسل.
5. أرسل صورة — يجب أن يخبرك أن هذه النسخة تدعم النصوص فقط.
6. جرّب من حساب غير موجود بالقائمة — يجب أن يمنع محادثة AI ما دام `ALLOW_ALL_USERS=false`.
7. راجع Usage في OpenAI وسجل Railway. يظهر عدد توكنات الإدخال والإخراج للردود الناجحة، دون تسجيل نصوص المحادثة أو المفاتيح.

## 6. تشغيل محلي اختياري

ثبّت Python 3.12، ثم افتح Terminal داخل مجلد المشروع. أوامر Windows PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
```

حرّر `.env` وأدخل المفاتيح. لا تكرر أمر النسخ بعد إدخالها حتى لا تستبدلها. ثم:

```powershell
.\.venv\Scripts\python.exe bot.py
```

على macOS/Linux استخدم `python3 -m venv .venv`، ثم `.venv/bin/python -m pip install -r requirements.txt`، وانسخ المثال بـ `cp .env.example .env` ثم شغّل `.venv/bin/python bot.py`.

أوقفه بـ Ctrl+C. لا تشغله محليًا بالتوكن نفسه أثناء عمل نسخة Railway.

## 7. الاختبارات الآلية

بعد تثبيت المكتبات، نفّذ:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

تستخدم الاختبارات خدمات وهمية؛ لا تحتاج مفاتيح ولا تستهلك API. تغطي منع الحسابات غير المصرح بها، حفظ السياق ومسحه، حدود الطلبات، فشل API، وتقسيم الردود الطويلة مع الرموز التعبيرية. لا تعوّض الاختبار الحي في الخطوة 5.

## 8. حل المشاكل

| المشكلة | ما يجب مراجعته |
|---|---|
| `Configuration` عند التشغيل | تأكد من وجود المتغيرين المطلوبين وصحة الأرقام والقيم المنطقية |
| `InvalidToken` أو `401` من Telegram | انسخ توكن BotFather كاملًا دون مسافات، وحدّثه إن ألغيته |
| البوت يقول إن الحساب غير مفعّل | أرسل `/id` وأضف الرقم إلى `ALLOWED_USER_IDS` ثم طبّق التغييرات |
| لا يوجد رد نهائيًا | افتح البوت واضغط Start، تحقق أن النشر يعمل وأنه نسخة واحدة وأن متغيراتك على الخدمة الصحيحة |
| خطأ تعارض polling / `Conflict` | أوقف أي نسخة أخرى تستخدم التوكن نفسه، بما فيها تشغيل محلي أو نشر قديم |
| `OpenAI API status=401` | راجع مفتاح OpenAI وصلاحياته |
| `OpenAI API status=403` أو `404` | راجع إتاحة النموذج لحسابك وصلاحيات المشروع واسم `OPENAI_MODEL` |
| `OpenAI RateLimitError` | قد يكون حد الطلبات أو نفاد الرصيد؛ راجع Usage وBilling قبل إعادة المحاولة |
| مهلة أو انقطاع اتصال | راجع حالة المزود واتصال Railway، ثم حاول لاحقًا |
| الجواب ناقص | ارفع `MAX_OUTPUT_TOKENS` بحذر أو اطلب إجابة أقصر |
| فقدان الذاكرة | طبيعي بعد إعادة التشغيل أو النشر أو `/reset`؛ لا توجد قاعدة بيانات |

## ملاحظات التشغيل والتكلفة

- هذه نسخة بسيطة للاستخدام الشخصي أو مجموعة صغيرة، وتعالج الرسائل بالتتابع. سؤال بطيء قد يؤخر الرد على المستخدم التالي.
- آخر 4 أزواج سؤال/جواب تُعاد مع السؤال الجديد إلى OpenAI؛ تقليل `HISTORY_TURNS` يقلل حجم الإدخال. `/reset` يمسح السياق المحلي فقط ولا يحذف رسائل Telegram أو سجلات المزود.
- تُحفظ بيانات آخر 1000 مستخدم في الذاكرة، ثم يُزال الأقل استخدامًا عند امتلائها. لا يوجد تخزين دائم.
- يتجاهل التشغيل رسائل Telegram المعلقة السابقة حتى لا ينفذ طلبات قديمة مدفوعة بعد انقطاع طويل. أعد إرسال سؤالك إذا صادف وقت إعادة النشر.
- `store=False` يعطّل تخزين كائن Responses للاسترجاع، وليس ضمانًا بعدم وجود سجلات لدى المزود؛ راجع سياسة بيانات OpenAI.
- حدود طول الرسالة والرد والفاصل الزمني تقلل الاستهلاك، لكنها ليست سقفًا ماليًا يوميًا. تابع الاستخدام، واحصر الوصول بحسابك إذا كانت ميزانيتك صغيرة. المحاولات المتكررة قد تكون مدفوعة أيضًا.
- يدعم النصوص فقط ولا يضيف بحثًا على الإنترنت أو أدوات أو صورًا أو صوتًا.

## الملفات

- `bot.py`: البوت وواجهة OpenAI Responses.
- `requirements.txt`: إصدارات المكتبات المثبتة للاختبار.
- `Dockerfile`: بيئة Python 3.12 وتشغيل البوت.
- `railway.json`: إعدادات البناء والتشغيل وإعادة المحاولة.
- `.env.example`: نموذج المتغيرات دون أسرار.
- `.gitignore` و`.dockerignore`: استبعاد ملفات الأسرار والبيئة المحلية.
- `tests/test_bot.py`: اختبارات بدون اتصال خارجي.
